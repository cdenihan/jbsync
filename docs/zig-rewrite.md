# Zig 0.17.0 rewrite experiment

This branch contains a standalone implementation of jbsync in Zig. `zig build`
produces `zig-out/bin/jbsync` for **Apple Silicon Macs only**, without invoking Rust
or linking its runtime. The Rust source remains the behavioral baseline and release implementation.
Both build systems reject unsupported targets. Release packaging and the
installer now accept only ARM64 macOS; this PR does not publish a release.

The scaffolding was generated with the installed **`zig init`**, then adapted
for this application. The package fingerprint is the one generated by Zig.
Development follows the [Zig 0.17.0 language reference](https://ziglang.org/documentation/0.17.0/)
and the installed toolchain's standard-library source.

## Build and test

Install/use Zig 0.17.0, Git, and Python 3 for the CLI fixtures:

```sh
zig version                        # 0.17.0
zig build                          # Debug binary
zig build test --summary all        # library tests
zig build -Doptimize=ReleaseSafe
python3 tests/zig/integration.py zig-out/bin/jbsync
zig build run -- --help
```

If the default Zig cache is inaccessible, set `ZIG_GLOBAL_CACHE_DIR` to a
writable directory. `mise run zig-ci` performs formatting, unit, CLI, differential
and platform checks. The Rust tasks remain available.

For direct Rust comparisons and a disposable benchmark:

```sh
cargo build --locked --example validation_oracle
zig build validation -Doptimize=ReleaseSafe
python3 tests/zig/differential.py zig-out/bin/jbsync-validation target/debug/examples/validation_oracle
cargo build --locked --release
python3 tests/zig/integration.py target/release/jbsync --rust-baseline
python3 tests/zig/benchmark.py zig-out/bin/jbsync target/release/jbsync
sh tests/zig/platform.sh
```

`.github/workflows/zig.yml` runs the same validation on Apple Silicon macOS
in Debug, ReleaseSafe and ReleaseFast modes. It uploads each experimental
binary. The Rust workflow runs its complete original suite, formatting, Clippy
and the shared CLI scenarios. No Intel Mac, Linux or Windows artifacts are built.
The previous Windows failure was CRLF checkout formatting; `.gitattributes`
now enforces LF. The failing Linux runtime job was removed with Linux support;
its `Unexpected` runtime failure was not diagnosed or claimed as repaired.

All CLI scenarios create temporary IDE directories and Git repositories. They
never point at the user's actual JetBrains settings or call real IDE launchers.

## Design

- `src/root.zig` exports the library; `src/main.zig` owns process initialization,
  output, and the process-lifetime arena. Every allocating library operation
  takes the caller's allocator explicitly. Trees, projections, configuration,
  and planned writes live in that arena. Tests release the arena with `defer`.
- `std.process.Init` supplies `std.Io`, arguments and the environment. Filesystem
  and child-process operations receive the I/O context explicitly. There is no
  libc binding or third-party Zig package. Git transports store history; the OS
  hostname utility supplies the default identity when environment variables do
  not provide it.
- `xml.zig` holds ordered children and deterministic sorted attributes, decodes
  entities, handles CDATA and rejects malformed projections. Repeated addresses use a
  whole-file merge; writeback preserves all siblings and refuses replacement
  when it would discard private/default settings.
  Domain elements with no value attribute are represented by their existence.
  Address delimiters inside identifiers are escaped. Incoming ordered children
  are applied in donor document order, including indices above nine.
- `merge.zig` performs pure three-way reconciliation of XML leaves, JVM option lines (including their order and repetitions),
  and opaque store metadata. It returns explicit changes and conflicts.
- `config.zig` reads the TOML forms used by jbsync's configuration and saved
  defaults. `settings.zig` handles discovery, manifests, pruning, product
  metadata, exclusions, and product-specific VM options names. Roaming policy
  data is carried forward from the Rust implementation in `policy.zig`.
- `engine.zig` converges the IDEs through up to four passes. All file changes
  are planned in memory, so `--prefer neither` can abort before applying any
  settings, store, backup, or baseline writes. Dry runs use those same staged
  views. Remote sync policy takes effect within the same run.
- `files.zig` checks paths below trusted roots, refuses symlink settings paths,
  writes and syncs a temporary file before atomic replacement, and takes an OS
  advisory lock around a sync. Replacement preserves existing file permissions. Backups are saved before originals change and
  preserve pre-run bytes even across multiple convergence passes. Ten backup
  runs are retained. The application directory is private. Staged disk reads and directory lists are
  cached per sync; no-op writes are dropped. Before committing, every planned
  destination is rechecked for symlinks and concurrent edits. Git internals and
  excluded IDE caches are skipped during traversal.
- `git.zig` reconciles file trees structurally before recording the remote as
  an `ours` merge parent. It distinguishes an empty remote from fetch failures,
  retries publishing even when no new commit is needed, and preserves binary
  bytes using the same `* -text` store attributes as Rust.
- `plugins.zig` uses `std.zip` to read JAR descriptors, writes the compatible
  JSON manifest, checks build ranges/modules/incompatibilities and scoped
  rules, and plans managed dependencies before their dependents. Capabilities do not
  imply installation; bundled IDs and actual plugin presence are tracked
  separately. Build ranges compare numeric components, including product codes. IDE launchers
  run only after conflict validation. Plugin directories are never copied.

## Tested behavior

The Zig library suite covers canonical XML, entities, child order, named domain
presence, escaped addresses, disjoint edits, conflicts and policies, deletions,
JVM flags, configuration layering, pruning, numeric builds, glob selectors,
plugin descriptors and compatibility, and twelve-item ordered lists.

The CLI suite covers:

- multiple IDEs contributing disjoint edits, convergence, backups and idempotence;
- second-machine adoption, divergent Git histories, and two-machine disjoint edits;
- conflict policy and `neither` leaving all settings bytes unchanged;
- dry-run snapshots and plans matching the subsequent sync;
- privacy pruning with surgical preservation of unshared IDE content;
- incoming exclusions and machine overrides;
- unlaunched IDE factory defaults and launch gating;
- compressed JAR descriptors, plugin manifests and idempotent rule commands;
- product-specific VM options and collect-only followed by a full sync;
- deletion propagation, lock contention, symlink rejection, invalid config,
  command-specific flags, and builtin sync switches.

The shared CLI suite has 26 scenarios, including rapid backup retention,
permission preservation, real XML corpus convergence and subsequent edits,
plugin launchers simulated with a local executable, capability/bundled decisions,
managed plugin dependencies, failed fetches, selectors and immediate remote policy.

The differential suite makes **2,688 deterministic comparisons** with a freshly
built Rust oracle: all 14 real XML fixtures, Unicode/entities/attribute whitespace,
1,500 generated XML merges across all policies, 192 add/delete/tombstone cases,
450 JVM option merges, glob cases and 320 plugin compatibility combinations.
It compares semantic XML with ordered children rather than attribute order.
The native suite also injects allocation failures and tests concurrent-edit
preflight checks, parser depth limits and malformed XML.

The fresh Rust baseline passed its 143 active tests (one optional live-corpus
test is ignored). The shared CLI runner's `--rust-baseline` mode exercises 19
matching scenarios and explicitly skips seven known differences: Rust writes
under `--prefer neither`, coalesces rapid backups by second, suppresses failed
fetches, skips symlinks rather than rejecting the sync, loses edits to repeated
IntelliLang addresses, retains a deleted shared file in the other machine, and
applies incoming policy on the next run. Zig's stricter checks remain enabled.
Argument errors use exit status 2 in Rust and 1 in Zig.

The benchmark creates two disposable IDEs with 200 settings files, 4,000 leaves
and 2,000 excluded cache files, then times five settled syncs. Local ReleaseSafe
medians were 60.2 ms after optimization, 70.5 ms before, and 67.3 ms for Rust
release (about 15% faster than the original Zig version). These local results
include Git/process overhead, are workload-specific and are not CI thresholds.
No claim is made about Marketplace performance or live IDE behavior.

## Remaining parity and release work

This is an experiment for review and testing, not a release migration:

- **Self-update is unavailable.** Current releases contain Rust binaries. The
  Zig `update` command explains this and exits unsuccessfully rather than
  replacing the experiment with a Rust binary. Release packaging remains Rust-based until the experiment is accepted.
  The narrowed installer retains checksum/version verification and atomic
  installation; Zig self-replacement needs separate implementation/validation.
- **TOML is a documented subset.** Basic/literal strings, booleans, integers,
  arrays (including multiline arrays), ordinary/dotted/quoted tables, arrays
  of tables and inline maps are supported. Multiline strings, floats and dates
  are rejected. This is not a general TOML 1.0 parser; configuration using
  unsupported syntax must be simplified or the parser replaced before rollout.
- Shell completions cover top-level commands. The Rust completion output and
  terminal styling/progress/report layout have not been replicated exactly.
- Lossless XML equivalence has fixture coverage; the committed 14-file real-world
  corpus is compared with Rust; a fresh live-installation scan remains outstanding. Mixed-content XML is unsupported by
  the structured DOM and stays opaque; DTD/entity definitions are unsupported.
- Actual Marketplace downloads, running IDE reload behavior, and installation
  metadata discovery across real Toolbox layouts need live validation.
- Library callers provide an arena whose lifetime covers their entire operation.
  Allocations are bounded per file/descriptor. A synthetic speed benchmark is
  included; peak memory on large live installations remains unmeasured.

For an isolated manual trial, use a dedicated `--config-dir`, a copied IDE
configuration root, and a disposable Git remote. Start with `status` or
`sync --dry-run --no-install-plugins` before applying a plan.
